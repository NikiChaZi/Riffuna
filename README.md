# Riffuna 0.1.3

Личный музыкальный плеер для Windows на Python и PySide6. Источник поиска и воспроизведения — YouTube. Интерфейс: графитовые поверхности, тёплый текст и коралловый акцент, без градиентов.

## Запуск

Готовая сборка: **`dist\Riffuna\Riffuna.exe`**. Вся папка `dist\Riffuna` нужна для работы; переносить следует её целиком.

Из исходников: дважды нажать **`run.cmd`** либо выполнить:

```powershell
uv sync --extra dev
.\.venv\Scripts\python.exe launch.py
```

Для части роликов yt-dlp использует JavaScript runtime. Поддерживается установленный Node.js, который приложение находит через PATH. Python и библиотеки Qt включаются в готовую сборку; Node.js в неё не включён.

## Возможности первого прототипа

- Поиск по названию, исполнителю или ссылке на отдельный ролик YouTube.
- Поиск студийных записей в YouTube Music и проверенных музыкальных загрузок YouTube: OST, extended, ремиксы, мэшапы, slowed и sped-up. Клипы, live, реакции, разборы и длинные зацикливания исключаются фильтром метаданных.
- Сортировка по релевантности или просмотрам среди найденных музыкальных записей; загрузка дополнительных результатов до 120, если источник их возвращает.
- Воспроизведение, пауза, перемотка, громкость, повтор одного трека или всей очереди.
- Перемотка и громкость по клику или перетаскиванию; при наведении отображаются время и проценты.
- При перемотке звук кратко приглушается до новых аудиоданных и плавно возвращается, чтобы скрыть артефакты перехода.
- Кнопка «Вывод ▾» рядом с громкостью: динамики, наушники или системный выход. Выбор сохраняется; при отключении устройства включается системный выход, при возвращении восстанавливается выбор.
- Добавление треков в очередь и переход к следующему/предыдущему.
- Локальные лайки, история фактически запущенных записей и восстановление очереди после перезапуска.
- Оригиналы и обработки остаются отдельными записями по ID ролика.
- Фоновая подготовка первых двух результатов, записи под курсором и следующего трека очереди. Восстановленная очередь также подготавливается без autoplay.
- Общий буфер аудио в RAM для старта и перемотки: загруженные байты повторно используются без открытия нового соединения.
- Двойной щелчок запускает запись; контекстное меню открывает её на YouTube.

Наличие записи в поиске не гарантирует доступность воспроизведения: возможны ограничения YouTube и правообладателя. Приложение использует неофициальные клиенты YouTube; изменения сервиса могут потребовать обновления зависимостей. Использование контента должно соответствовать применимым условиям и разрешениям.

Фильтр опирается на тип результата и метаданные источника: ошибочно подписанные публикации могут пройти его. Первое подключение к новому потоку и переход к ещё не загруженному участку зависят от сети и ответа YouTube; мгновенный холодный старт не гарантируется.

Собственный рекомендательный движок, жанровая разметка, Android-клиент и загрузка аудио для офлайн-прослушивания в этот прототип пока не входят.

## Данные

Библиотека хранится в `%LOCALAPPDATA%\Riffuna\library.sqlite3`, технический журнал — в соседнем `application.log`. Лайки локальные: они не меняют аккаунт YouTube. Полностью загруженные аудиофайлы до 24 МиБ сохраняются в соседней папке `audio-cache`: общий лимит 1 ГиБ, при заполнении удаляются давно не использованные записи. Кэш сохраняется после перезапуска и не имеет таймера очистки. Частичные загрузки и файлы больше 24 МиБ продолжают передаваться потоково. Подписанные адреса хранятся только в памяти. Прямой запуск трека не добавляет его в очередь; для этого есть кнопка + или «Слушать всё».

Для тестовой библиотеки можно установить `MUSICDESK_DATA_DIR`. Изменение отображаемого названия приложения настраивается в `musicdesk/branding.py`.

## Разработка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\build.ps1
```

`build.ps1` создаёт сборку PyInstaller с Qt Multimedia и JS-компонентами yt-dlp. На время сборки скрипт изолирует PATH от DLL посторонних программ и восстанавливает его при завершении. Скрипт запускается из папки проекта; виртуальное окружение должно быть подготовлено заранее.

Код разделён на источник YouTube (`youtube.py`), транспорт и ограниченный RAM-буфер аудио (`relay.py`, `audio_buffer.py`), управление воспроизведением (`playback.py`), библиотеку SQLite (`storage.py`) и интерфейс (`window.py`, `widgets.py`, `style.py`). Локальный адаптер аудио слушает только `127.0.0.1`, поддерживает HTTP Range для перемотки и выдаёт лишь текущий поток по случайному адресу.

Тесты воспроизведения используют сгенерированное тестовое аудио с выключенным звуком; обычный набор тестов не обращается к YouTube.

Для явной проверки поиска, декодированного звука и перемотки с выключенным звуком: `Riffuna.exe --diagnose`. Добавление `--prepared` отдельно измеряет подготовленный старт и записывает время подготовки. Результат записывается в `diagnostic.json` в каталоге данных; диагностическая библиотека отделена от пользовательской.

Замеры из исходников: `.\.venv\Scripts\python.exe scripts\benchmark_playback.py VIDEO_ID` и тот же вызов с `--prepared`. Измеряется первый декодированный аудиобуфер, а при перемотке — буфер с временной отметкой нужного участка, а не только смена состояния Play.
