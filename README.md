# Riffuna 0.2.1

Локальный музыкальный плеер для Windows на Kotlin и Compose Multiplatform. Источники музыки — YouTube и локальные аудиофайлы; библиотека, аудиокэш и музыкальные рекомендации работают на устройстве. Удалённый сервер для обычного использования не нужен.

## Запуск

Открой **`Riffuna.exe`** в корне проекта. Рядом должна находиться папка **`Riffuna.runtime`** — она содержит приложение и встроенные среды выполнения. Устанавливать Java, Node.js или Python пользователю готовой сборки не требуется. `run.cmd` для обычного запуска не используется.

Лайки, история, плейлисты, очередь, настройки, выбранные записи и кэш находятся в **`%USERPROFILE%\.riffuna`**. Запуск из другой папки не создаёт другую библиотеку. Один экземпляр приложения работает с одной библиотекой; путь и блокировка совместимы с предыдущей версией.

Актуальный выпуск — **[Riffuna 0.2.1](https://github.com/NikiChaZi/Riffuna/releases/tag/v0.2.1)**. Скачай `Riffuna-0.2.1-windows-x64.zip`, распакуй целиком в отдельную папку и открой `Riffuna.exe`. Папка `Riffuna.runtime` должна оставаться рядом. При переходе с Qt прежняя библиотека подхватывается автоматически; удалять `%USERPROFILE%\.riffuna` не нужно.

## Возможности

- Локальные MP3/FLAC/OGG/Opus/M4A/AAC/WAV/WMA: импорт файлов или папки, чтение тегов, поиск и воспроизведение без YouTube. Оригиналы остаются на своих местах.

- Музыкальная выдача с исключением клипов, live, реакций, разборов и длинных зацикливаний. Slowed, sped-up, мэшапы, ремиксы и OST сохраняются при прохождении проверок источника и соответствия запросу.
- Поиск по названию, исполнителю или ссылке на аудиозапись. Дополнительные результаты до 120. Сортировка по релевантности или реальным просмотрам среди найденных и проверенных записей.
- Лайки, история и плейлисты с названием, описанием, копированием, пакетным добавлением и изменением порядка.
- Ctrl/Shift/Ctrl+A для выделения, групповые действия, локальный фильтр и сортировка. Сортировка не изменяет сохранённый порядок плейлиста; ручное перемещение доступно в исходном порядке без фильтра.
- Очередь с запуском с начала, перетаскиванием, удалением, приоритетом «следующим», перемешиванием и повтором. Очистка очереди не обрывает текущую музыку. Обычное прослушивание найденного трека не добавляет его в очередь само по себе.
- Нативный звук libmpv, выбор устройства вывода, автоматическая реакция на отключение устройства. Сохранены настройки непрерывного вывода, использованные для Buds3 FE.
- Перемотка и громкость по клику или перетаскиванию; подсказки времени и процентов. Подготовка следующей записи и постоянный дисковый кэш до 1 ГиБ, без удаления по таймеру.
- Главная с реальными обложками истории и лайков; раскрытый плеер с переходом обложки и режимом фокуса на тексте.
- LRCLIB, локальный LRC/TTML, enhanced LRC и дополнительный источник пословных таймкодов. Точные слова подсвечиваются по таймкодам; при наличии только построчного LRC подсветка слов расчётная и так подписана. Несовпадающая редакция или длительность не получают чужую синхронизацию автоматически.
- «Другие записи» с проверкой названия, исполнителя, длительности, музыкальной обработки и метаданных. Сохранённый выбор остаётся доступен. Надпись «без цензуры» в названии не подтверждает содержимое аудио.
- «Резонанс»: отдельно обученные музыкальные Two-Tower и CatBoost, работающие локально через ONNX Runtime. Каталог ограничен обучающими данными. Для неизвестных исполнителей используются только доступные публичные жанровые теги уровня исполнителя.
- Навигация назад/вперёд, горячие клавиши и настройка уменьшения движения. Палитра: графит, тёплый текст, коралл; без декоративных градиентов.

## Разработка и сборка

Модули: `shared` — общее ядро, `desktopApp` — Compose UI и платформенные реализации, `source-runtime` — закреплённые YouTube.js и Undici для запросов YouTube, прямого аудио и JavaScript-задач проигрывателя. HTTPS-аудио и проверка ссылки используют один транспорт; Kotlin получает диапазоны по локальному каналу с ключом процесса и сохраняет буфер/кэш. Python и Qt в поставку не включаются. Python остаётся инструментом обучения/экспорта моделей. Прежняя Qt-реализация сохранена в теге `v0.2.0` и ветке `legacy-qt`; в активном дереве её нет.

Нужны JDK 21, Node.js 24.5+ на машине разработчика, подготовленный libmpv и экспортированные музыкальные модели. Gradle Wrapper закреплён с SHA256; зависимости YouTube закреплены `package-lock.json`.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build_kotlin.ps1 -LiveTest
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install_kotlin.ps1
```

Сборка появляется в `dist/Riffuna-0.2.1`. Скрипт установки сохраняет прежний EXE в `.test-data/before-native-kotlin` и не переносит пользовательскую базу данных.

[Архитектура, проверки и границы переноса](docs/kotlin-migration.md). [Обучение музыкальных моделей](docs/music-recsys.md).

## Android

Сейчас проверяется Windows-версия. Общее ядро и интерфейсы источника, библиотеки и аудиодвижка подготовлены для следующей платформы. Android-цель и Media3 ещё не подключены; APK пока не выпускается.

## Лицензия

Собственный код Riffuna распространяется по PolyForm Noncommercial 1.0.0. Лицензии зависимостей сохраняются отдельно. Сведения о libmpv и встроенном Node.js находятся в `LICENSES` и в поставке приложения.

## Проверки изменений

`gradlew.bat spotlessCheck :shared:jvmTest :desktopApp:test` проверяет форматирование и Kotlin-код. GitHub Actions выполняет эти проверки на Windows, включая беззвучный нативный аудиовывод; сетевые проверки YouTube включаются отдельно. Проверка паритета обученной модели требует локально подготовленных артефактов. Python-тесты ML запускаются отдельно: `uv run --extra dev --extra evaluation pytest`.
