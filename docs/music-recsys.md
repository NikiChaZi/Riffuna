# Музыкальный recsys Riffuna

Это отдельный музыкальный домен. Веса, ID и коллекции MovieLens не используются и не изменяются.

## Данные и протокол

Music4All-Onion: https://zenodo.org/records/15394646 (DOI 10.5281/zenodo.15394646), CC-BY-4.0. Авторы и ссылка сохраняются в ATTRIBUTION.json внутри пакета модели. Загружены только агрегированные взаимодействия, жанровые признаки и теги; аудио/полные тексты не скачиваются для обучения. Базовое соответствие ID–artist–song взято из закреплённого зеркала исходного CSV: https://huggingface.co/datasets/Leon299/music4all/tree/c409d02. Перед публичной раздачей каталога/весов требуется отдельно проверить условия базового Music4All и зеркала; локальная проверочная сборка не является публикацией датасета.

Скрипт проверяет MD5 файлов Zenodo. Из 50 016 042 агрегированных пар выбраны целиком пользователи uid % 23 == 0, а не начало файла. После фильтрации: 4 790 пользователей, 49 668 треков, 2 127 622 пары tower-train, 21 632 ranker-пары, 21 649 test-пар. Поддержка каталога и популярность вычислены только из tower-train. Пары одного пользователя разнесены между train/ranker/test без пересечений. Разбиение случайное, не временное: агрегированные счётчики не дают хронологию. Это ограничивает выводы о будущих прослушиваниях.

Профиль пользователя строится из музыкальных признаков его истории. Item tower и user tower — MLP 128→64 с LayerNorm/ReLU и нормализацией; InfoNCE с in-batch negatives, явное исключение целевого трека из входной истории. На эпоху сэмплируется до 40 обучающих целей пользователя, контекст — до 20 других train-треков; пять эпох на CUDA. Непрослушанный кандидат не является подтверждённым дизлайком.

CatBoostRanker использует отдельные ranker-взаимодействия и восемь числовых признаков: близость двух башен, жанровое сходство, долю исполнителя в истории, train-популярность, размер профиля, плотность жанров, максимальное жанровое сходство и сходство контента. Для его обучения положительные цели добавляются в пул; на тесте цели не добавляются — оценивается реальный top-200 retrieval. Ранняя остановка использует отдельные группы пользователей ranker-части. Test не применяется для подбора параметров в этом запуске.

## Проверенный результат первого запуска

Усреднение на отложенных взаимодействиях 1 000 пользователей:

| Метод | Recall@20 | NDCG@20 |
|---|---:|---:|
| Train-популярность | 0.01515 | 0.00958 |
| Жанровое сходство | 0.01130 | 0.00550 |
| Two-Tower | 0.03418 | 0.01917 |
| Two-Tower + CatBoost | 0.04508 | 0.02985 |

Retrieval Recall@100: 0.09435. Это офлайн-метрики выбранной когорты и протокола, а не вероятность понравиться конкретному человеку. Каталог старый, современных русскоязычных исполнителей часто нет.

## Холодный старт и идентичность

Точное совпадение artist/title и совпадение по известному исполнителю учитываются раздельно. Для отсутствующих исполнителей загружаются публичные artist tags с Last.fm, максимум шесть неизвестных исполнителей за запрос, до трёх параллельных загрузок с ограничением частоты, таймаутом и кэшем. В признаки попадают только наблюдаемые теги, совпавшие с жанрами обучения. Это жанровый профиль исполнителя, не анализ аудио конкретной записи. Доступность источника не гарантируется. Если данных недостаточно, возвращается insufficient_catalog_coverage, а не случайный список.

Кандидаты модели сначала являются метаданными каталога. По нажатию Play выполняется строгий музыкальный поиск YouTube с проверкой исполнителя, названия и обработки; неподходящая запись не подменяет результат автоматически. Новые кандидаты вне обучающего каталога пока не дообучаются автоматически. При выборе slowed/ремикса не используется чужая синхронизация текста.

## Выполнение в Kotlin 0.2.0

Windows-приложение выполняет user tower и CatBoost через ONNX Runtime, без Python и удалённого API. Экспорт: `scripts/export_music_onnx.py`; сборка: `scripts/build_kotlin.ps1`. Проверены числовые оценки и порядок рекомендаций относительно исходной модели. Атрибуция обучающих признаков включена в `LICENSES/Music4All-Onion-ATTRIBUTION.json`. Ниже сохранены сведения о прежней Qt-реализации и инструментах обучения.

## Историческая Qt-реализация и обучение

В обычном EXE выполняются NumPy-экспорт user tower и числовой JSON-экспорт симметричных деревьев CatBoost. Эти вычисления сверены с исходными библиотеками: максимальная ошибка user tower < 1e-7, на 1 000 тестовых числовых входах ranker — 0.0. PyTorch и CatBoost в EXE не требуются. Загрузка модели и подбор выполняются в worker, аудиодвижок не заменяется.

Если работает локальный API на 127.0.0.1:8766, клиент использует его. При недоступности API выполняет ту же модель локально. API принимает только музыкальный контракт domain=music/schema=1. Сервис связывается только с loopback; внешнее размещение требует отдельной авторизации.

Опциональные RIFFUNA_QDRANT_URL и RIFFUNA_REDIS_URL подключают существующую инфраструктуру. Музыкальная Qdrant-коллекция и Redis-ключи имеют отдельный префикс и fingerprint весов, не затрагивая movies. По умолчанию поиск точный NumPy по 49 668 векторам; наличие Qdrant/Redis в этой среде не подтверждено (порты были закрыты), интеграция с ними в этом запуске не проверялась. При повреждённом/неверном контракте сервер не заменяется скрыто локальным режимом.

Разработка/переобучение:

```powershell
uv sync --extra dev --extra recsys
.venv\Scripts\python.exe scripts/download_music_training.py
.venv\Scripts\python.exe -m riffuna_recsys.train --epochs 5
.venv\Scripts\python.exe -m riffuna_recsys.service --model-dir .test-data/music-training/model
.\build.ps1
```

Для обычной сборки достаточно desktop/dev-зависимостей и уже обученных файлов .test-data/music-training/model. scripts/prepare_music_model.py переносит в build/music-model только явный список весов/каталога и атрибуцию; личные лайки, история, аудио, LRC и кэш метаданных не упаковываются. Артефакты и исходные данные исключены из Git. Код обучения остаётся в riffuna_recsys, чтобы воспроизводить и совершенствовать модель.
