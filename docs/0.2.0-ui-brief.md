# Expanded player — UI boundary for Riffuna 0.2.0

The current checkout is C:/Projects/free-spotify, branch codex/0.2.0-player, base v0.1.4. This UI contribution adds isolated Qt Widgets components only. The main chat owns window.py integration and backend work in the shared checkout. This contribution does not edit those files, the audio engine, buffering, audio routing, seek implementation, storage, YouTube search, the working EXE or packaging.

## Layout and motion

- An overlay inside the existing central widget, with two desktop columns: cover/recording metadata/controls on the left, lyrics on the right. Intended host size: 1280x800, minimum 1000x650.
- A small-cover trigger remains keyboard accessible. Cover geometry travels from the trigger to the left-column center (240 ms); contents fade in (160 ms). Collapse reverses the flight. Rapid reversal starts at the current visual value. Resizing finishes/rebases the cover flight, with no stale overlay.
- Lyrics have a softly moving focal line, subdued neighboring lines and a visible keyboard cursor. Logical selection updates immediately from actual position. Paused changes and seeks snap to the correct location; animations never advance the playback clock.
- A local reduced-motion switch immediately settles all active transitions. The controller can supply the same MotionPolicy to other UI components later; no storage/preferences are written here.

## New modules

- `musicdesk/motion.py`: MotionPolicy, interruptible Tween and PageFade, using QVariantAnimation in the GUI thread.
- `musicdesk/lyrics_view.py`: immutable view data, controller-payload adaptation, timeline lookup, painted/scrollable lyric view and all six states. No network.
- `musicdesk/expanded_player.py`: ExpandedPlayer, ExpandableCover trigger, artwork flight, playback controls and request/result guards.
- `musicdesk/player_view_binding.py`: optional thin binding to the existing Playback signals and methods. No engine creation or audio processing.

## Integration contract (window.py changes remain outside this task)

1. Replace only the bottom cover's widget class with `ExpandableCover(artwork, 56)`. It preserves Cover's set_url/cache behavior and emits `activated` on click/Enter/Space.
2. Construct `ExpandedPlayer(parent=central_widget)` and resize it to that parent's rect. Use `open_from(trigger)` to expand and `collapse()`/Esc to close. Focus returns to the trigger. The controller decides when to show/hide the normal central content. No autoplay is performed on open.
3. Either create `ExpandedPlayerBinding(view, playback, artwork=artwork)` or connect the explicit view setters/signals. Binding must be disconnected when replaced; it imports no playback implementation.
4. The view emits `lyrics_requested(video_id, request_token)`. A provider returns `set_lyrics(video_id, request_token, LyricsDocument(...))`. Both ID and request token must match. Retry creates a fresh token; track changes clear existing text immediately.
5. `LyricsDocument(state, cues=(), text='', source='', timing_confirmed=False)` accepts loading/synced/plain/instrumental/notfound/error. Synced cues require explicit confirmation of timings for this exact recording. Otherwise the UI presents plain text without a sync claim. There is no automatic speed scaling, censored/uncensored inference or title-based version matching.
6. `apply_lyrics_payload(recording_id, payload)` adapts LyricsController.changed directly. The controller owns stale-result suppression and LRC parsing. `provider_lrc`/`local_lrc` plus `metadata_duration`/`user_import` permit synchronized presentation; other timed content becomes plain text. `not_found` is mapped to the UI state. `import_requested(video_id)` asks the parent to choose a file and call controller.import_lrc(track, path); the component does not access files. No timestamps are fabricated.
7. Feed actual `position_changed` values (milliseconds) through `set_position`, state through `set_playback_state`, and duration/seekability through their setters. Outgoing `seek_requested(ms)` is only a request; it never becomes the lyric clock until the actual position arrives.
8. Version selection is a future integration point: enable `set_version_selection_available(True)` only when the controller can handle `version_requested(video_id)`. It is hidden by default. Lyrics always belong to the selected video ID. Recsys/“Резонанс” UI is absent.
9. Toggle/previous/next/repeat/shuffle/volume are intent signals. Likes, queue visibility, output selection and version UI remain controller-owned. The expanded controls reuse PointerSlider's existing one-commit-per-gesture behavior.

## Ready-to-use wiring

```python
# Create the provider connections before binding: initial track sync emits a request.
view = ExpandedPlayer(central_widget)
view.lyrics_requested.connect(lambda recording_id, token: lyrics_controller.load(playback.current, force=True))
lyrics_controller.changed.connect(view.apply_lyrics_payload)
view.import_requested.connect(choose_lrc_for_recording)  # QFileDialog + controller.import_lrc
binding = ExpandedPlayerBinding(view, playback, artwork=artwork)
small_cover.activated.connect(lambda: view.open_from(small_cover))
# Like/output/queue remain parent-owned; connect these to existing handlers.
```

When using `LyricsController.changed`, that controller owns rejection of stale network results for repeated requests on the same recording. The standalone `set_lyrics(id, token, document)` path additionally validates request tokens. `apply_lyrics_payload` validates both the signal's recording ID and payload.recording_id. Its Qt Slot declaration delivers cross-thread signals to the GUI thread.

The local reduced-motion control is exposed through `view.policy.set_reduced(bool)`. Closing returns focus, and Tab/Shift+Tab stay inside the expanded surface. Manual lyric browsing preserves the actual active line; “К текущей строке” returns to follow mode. The view never infers uncensored/original status and never changes audio speed.


## Page transitions (parent wiring only)

`PageFade(stack, policy, duration=160)` attaches to QStackedWidget.currentChanged. It selects no page itself, blocks no input and performs no deferred navigation. It fades in the already-selected page for 150–180 ms, continuing from the current opacity on rapid switches. Reduced motion, hidden containers and detach settle at full opacity. An existing graphics effect is never overwritten: wrap the stack or detach its prior PageFade first.

```python
self.page_fade = PageFade(self.stack, self.expanded_player.policy)
# Existing setCurrentWidget/setCurrentIndex calls need no other change.
# Optional: self.page_fade.fade_current() for a content refresh in the same page.
# Before replacing it: self.page_fade.detach()
```
