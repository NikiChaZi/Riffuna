# Android MVP

Android собирается отдельно в `android/`, чтобы для Windows не требовался Android SDK. Модуль `android/core` — Android KMP library, который компилирует непосредственно исходники `shared/src/commonMain/kotlin`; копий контроллера и очереди нет. Общий код остаётся единственным источником поведения очереди, повторов, лайков и навигации.

## Устройство

- Android 8.0 / API 26 и новее; target SDK 36.
- Compose UI: графит, тёплый текст, коралл. Нативные экраны, а не сайт внутри WebView.
- Media3 ExoPlayer: аудиофокус, пауза при отключении наушников, HTTP Range, постоянный дисковый кэш до 512 МиБ, MediaSessionService и системное управление воспроизведением. Ключ кэша включает ID записи и формат `itag`.
- SQLite во внутреннем каталоге приложения: лайки, история, очередь, плейлисты и настройки. Данные Windows не читаются и не перезаписываются. Автоматической синхронизации устройств пока нет.
- Локальные файлы выбираются через системный Storage Access Framework с постоянным разрешением; произвольный доступ ко всему диску не требуется.
- Закреплённый YouTube.js 18.3.0 исполняется в системном JS-движке Android. Невидимый WebView загружает только локальные assets; не служит интерфейсом или аудиоплеером. Сетевые обращения выполняются через ограниченный HTTPS-мост OkHttp. Python, Node.js и внешний сервер в установленном приложении не нужны. Node.js используется только при обновлении встроенного JS-компонента разработчиком.
- Поиск MVP использует музыкальный каталог YouTube Music. Расширенный ограниченный поиск UGC/OST и проверка альтернатив из Windows ещё не перенесены.
- LRCLIB: только совпадение исполнителя, названия и длительности в пределах двух секунд. LRC подсвечивается по строкам. Пословные тайминги не выдумываются, если провайдер их не дал.
- Музыкальные ONNX-модели «Резонанса», импорт/экспорт библиотеки между устройствами, загрузки для офлайна и расширенный редактор плейлистов пока не включены в Android MVP.

Доступность YouTube определяется сетью телефона. Внешний сервер не требуется; при необходимости VPN включается на самом телефоне.

## Сборка

Нужны JDK 21, Gradle 8.14.3 (имеющийся wrapper в корне), Android SDK 36 и Build Tools 36.0.0. Исходники Java/Kotlin компилируются в JVM 17 для Android.

```powershell
$env:ANDROID_HOME = 'PATH_TO_ANDROID_SDK'
npm ci --prefix source-runtime --ignore-scripts
node scripts/build_android_source.mjs --restore-vendor
node scripts/build_android_source.mjs --check
.\gradlew.bat -p android spotlessCheck :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Проверочный APK: `android/app/build/outputs/apk/debug/app-debug.apk`. Это debug-сборка для ручной установки, а не готовый магазинный релиз. Подпись debug не должна использоваться для публичного production-релиза.

## Проверка на устройстве

```powershell
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n app.riffuna.android/riffuna.android.MainActivity
.\gradlew.bat -p android :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.liveNetwork=true
```

Инструментальные тесты используют отдельную базу: проверяют сохранение лайков/истории/очереди/плейлистов, а при явном `liveNetwork=true` — настоящий поиск, разрешение URL, HTTP 206 и беззвучное воспроизведение/перемотку Media3. Результаты сборки и реальные ограничения проверки записываются после выполнения, а не считаются успешными заранее.

## Проверенный результат

Проверка на BlueStacks / Android 11: 26 тестов общего ядра, 6 JVM-тестов Android-модуля и 5 инструментальных тестов прошли. Live-тест выполнил музыкальный поиск (10 результатов), скачал аудиопоток целиком (2 372 782 байта), подтвердил начало беззвучного воспроизведения Media3, паузу и перемотку. Отдельно проверены продолжение воспроизведения после сворачивания Activity, пауза через системную MediaSession, SQLite после повторного открытия и чтение диапазонов через границы чанков. Android lint завершился без ошибок; предупреждения о более новых версиях зависимостей остаются.

Media3 использует собственный upstream DataSource с последовательными диапазонами до 1 МиБ. Ссылки проверяются запросом конца записи; контентный токен воспроизведения хранится только в памяти. HTTPS-мост сохраняет явные заголовки источника: браузерный Request иначе удаляет User-Agent, из-за чего ссылка отдаёт начало записи, но отклоняет следующие диапазоны. Весь поток проверен отдельно от начала звука. Короткая проверка сворачивания не заменяет длительное прослушивание, проверку энергосбережения и Bluetooth на физическом телефоне.

Riffuna зафиксирована в портретной ориентации. Это проверено на реальном скриншоте приложения в BlueStacks. Тестовый APK имеет собственные название, иконку и Activity: без них установщик BlueStacks 5.22.168.1001 падал при регистрации пакета. Этот служебный пакет не входит в пользовательский APK.

Обновление JS-компонента: `npm ci --prefix source-runtime --ignore-scripts`, затем `node scripts/build_android_source.mjs`. Поиск и алгоритм выбора/проверки потока генерируются из того же закреплённого исходника, что используется Windows. `node scripts/build_android_source.mjs --check` проверяет синхронизацию и SHA-256 браузерного bundle. Изменённый компонент требует пересборки APK.
