# Переход Riffuna на Kotlin: состояние Windows-версии

Активная реализация — Kotlin/Compose в `desktopApp` и общее ядро в `shared/commonMain`. Python/Qt не участвуют в готовой поставке. Прежние Qt-исходники сохранены в теге `v0.2.0` и ветке `legacy-qt`; экспериментальный Flutter-каркас и технический Compose-экран убраны из активных модулей с сохранением копий в `.test-data`.

## Перенесённые сценарии Qt

| Область | Реализация |
| --- | --- |
| Библиотека | Совместимая SQLite, лайки, история, очередь и настройки в `%USERPROFILE%/.riffuna` |
| Плейлисты | Создание, название и описание, копирование, добавление/удаление, точная перестановка |
| Списки | Локальный фильтр, сортировка, Ctrl/Shift/Ctrl+A, групповые действия, перетаскивание |
| Очередь | С начала, приоритет следующей записи, shuffle/repeat, сохранение продолжения после удаления текущей, стабильная прокрутка |
| Навигация | Назад/вперёд с восстановлением локальных фильтров; клавиатура и справка |
| Аудио | libmpv/JNA, 48 кГц float stereo, непрерывный вывод, выбор/обновление устройств, перенос прежней настройки |
| Буфер и кэш | Единый HTTPS-транспорт Node/Undici; HTTP Range и кэш на Kotlin, до трёх буферов по 24 МиБ, целостные файлы с SHA256, LRU до 1 ГиБ без TTL |
| Локальная музыка | Независимый источник файлов/папок, нативные теги, постоянный индекс, поиск и офлайн-воспроизведение |

| Другие записи | Сопоставление произведения/обработки/длительности, ограниченная проверка метаданных и статичных кадров, сохранённый выбор |
| Тексты | LRCLIB на Kotlin, кэш, plain fallback, LRC/enhanced LRC/TTML/QRC, локальный импорт, проверяемое пословное обогащение |
| Модели | Локальные Two-Tower и CatBoost через ONNX; проверены оценки и порядок рекомендаций против исходной реализации |

Поиск альтернатив может вернуть пустой результат: отсутствие подходящей загрузки не заменяется произвольным видео. Названия публикаций не являются проверкой отсутствия цензуры. Аудиозаписи свыше 24 МиБ обслуживаются частями и сохраняются на диск последовательно, без полного RAM-буфера; итоговый кэш ограничен 1 ГиБ.

## Проверки

- `shared:jvmTest`: выбор нескольких записей, навигация, состояние очереди, shuffle, повтор, поздние ответы, реальное начало истории, выбор версии и устройство вывода.
- `desktopApp:test`: совместимость SQLite, HTTP Range и кэш, реальные libmpv pause/seek/error/device APIs, ONNX-паритет, музыкальные фильтры и форматы таймкодов.
- `SourceIntegrationTest`, `RIFFUNA_LIVE_TEST=1`: поиск, доступ к аудио, начало воспроизведения, пауза и перемотка через новый источник с нулевой громкостью.
- `NativeCatalogueTest`, `RIFFUNA_CATALOGUE_TEST=1`: отдельная проверка каталога, прямых ссылок, OST, текстов и поиска альтернатив. Зависит от состояния внешних сервисов.
- `desktopApp:renderUi`: реальный Compose UI рендерится вне экрана без открытия или управления окнами. Результаты `.test-data/ui-render`; база — отдельная копия, позиция текста является явно помеченной QA-фикстурой.
- `Riffuna.runtime/Riffuna.exe --diagnose --report PATH`: проверка упакованной среды, SQLite, native audio API, JS-компонента, моделей и иконки на временных данных без окон и без подключения к YouTube. Дополнительный флаг `--live` отдельно проверяет поиск, воспроизведение с нулевой громкостью, паузу, перемотку и продолжение через установленную среду.

## Сборка

`build_kotlin.ps1` создаёт ресурсы по белому списку, включает Node.js и Java runtime, не копирует старый PyInstaller helper и проверяет отсутствие Python/Qt DLL/bytecode. `install_kotlin.ps1` устанавливает единый `Riffuna.exe` с иконкой рядом с `Riffuna.runtime`, сохраняет прежний EXE и не меняет расположение пользовательской библиотеки.

Для обучения/экспорта музыкальных моделей Python остаётся инструментом разработчика. Экспорт:

```powershell
python scripts/export_music_onnx.py --source PATH_TO_TRAINED_MUSIC_MODEL --target build/kotlin-music-model
```

В `source-runtime` находятся ограниченный JSON-протокол, YouTube.js и Undici с закреплёнными зависимостями. Диапазоны аудио передаются в Kotlin по HTTP на 127.0.0.1 со случайным ключом процесса; внешний HTTPS использует тот же клиент, что проверяет поток. Поиск не загружает JS-проигрыватель заранее; сначала проверяются прямые исходные аудиодорожки, затем путь с расшифровкой подписи. JS-движок входит в приложение: от пользователя не требуется отдельная установка Node.js. На устройстве должны оставаться доступными сами источники музыки и текстов.

## За пределами Windows-переноса

Android/Media3 и APK, синхронизация устройств, отдельная система загрузок, системные медиаклавиши/Windows Media Controls, папки плейлистов и расширенные карточки артистов/альбомов не входили в реализованную Qt-базу и пока не выдаются за готовые функции.
