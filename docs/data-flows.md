# Потоки данных Riffuna

Область проверки: локальные клиенты Windows и Android в ветке codex/artist-privacy. Внешние сервисы также получают сетевые метаданные соединения, например IP-адрес или адрес прокси. Срок хранения у внешних сервисов из кода приложения определить нельзя. В штатном клиенте собственного сервера и автоматической отправки отчётов нет.

## Данные на устройстве

| Категория и назначение | Место и срок хранения | Удаление и передача |
|---|---|---|
| История, чтобы показать недавние записи и учесть прослушивания в локальной модели | Windows: %USERPROFILE%/.riffuna/library.sqlite3, таблицы plays и tracks. Предел в 100 относится к читаемым уникальным записям; автоочистка строк Windows не определена. Android: приватная databases/library.sqlite3, history ограничена 2000 последними строками. Строки tracks могут остаться после вытеснения | Отдельной очистки истории в проверенном интерфейсе нет. Windows: удалить данные профиля при закрытом плеере. Android: «Очистить хранилище» или удалить приложение. Пакет истории не передаётся. «Резонанс» обрабатывает историю локально, но для отдельных неизвестных исполнителей может запросить публичные теги у Last.fm |
| Лайки, плейлисты, выбранная запись, очередь и позиция | В той же SQLite каждого устройства. Лайки содержат ссылку на трек и дату или порядок, плейлисты — имя, описание и упорядоченные ID, настройки — ID/позицию, выбранные версии, громкость и режимы. Срок не определён | Снять лайк, удалить плейлист или трек из него, сбросить выбранную запись, очистить очередь или профиль. Снятие элементов из коллекции не гарантирует удаления соответствующей строки tracks. Имена плейлистов и списки лайков не отправляются. При запуске трека его отдельный ID уходит провайдеру |
| Поиск и навигация: внешний каталог и локальный поиск | Текущий запрос и результаты в памяти клиента. Кэш запросов YouTube.js в памяти рабочего процесса до 5 минут. Поиск внутри локального списка остаётся в памяти UI. Отдельной базы поисковой истории не найдено | Закрыть приложение; смена запроса заменяет текущий текст. В YouTube Music/YouTube идут введённый текст и параметры выдачи. Ссылка на запись превращается в ID ролика. Каталог использует имя при поиске профиля, ID артиста или релиза при открытии и токен продолжения при пагинации |
| Локальные пути и метаданные: импорт собственных файлов | Windows: local-files.sqlite3 хранит абсолютный путь, ID, название, артиста и длительность. Android: ключ local-uri:<id> содержит content URI, local-files — метаданные. SAF хранит разрешение чтения. Срок не определён | Удаление оригинала не очищает индекс. Для полной очистки нужен локальный сброс профиля, на Android также прекращается доступ приложения к документам. Автоматический поиск текстов локальных файлов отключён. Явная команда поиска артиста или текст, введённый в общий поиск, отправляет поисковый текст провайдеру |
| Кэш стриминга, сохранённый офлайн и обложки | Windows: audio-cache до 1 ГиБ, artwork до 128 МиБ, вытеснение по доступу, без срока по календарю. Явно скачанное лежит в offline-audio до ручного удаления. Лимит по умолчанию 5 ГиБ ограничивает новые загрузки. Android: cacheDir/audio, Media3 LRU до 512 МиБ; обложки управляются Coil. Закреплённое аудио хранится во внутреннем filesDir/offline-audio вместе с ID, названием, исполнителем, длительностью, вариантом записи, размером файла и SHA-256. Срок хранения не задан. Настройка лимита по умолчанию 1 ГиБ ограничивает новые загрузки | «Скачанное» удаляет закреплённые файлы. Для автоматического кэша Windows закрыть приложение и удалить соответствующую папку, в Android использовать системную очистку кэша. Закрепление использует те же запросы к YouTube и CDN, что обычный стриминг. Байты аудио обратно не отправляются |
| Кэш текстов, сопоставления и теги | Windows: lyrics, обычный результат 30 дней, отсутствие текста 1 час; дополнительная попытка пословной синхронизации 1 день при отсутствии и 30 дней при успехе. Это сроки повторного запроса, а не автоматического удаления файла. Импортированный LRC/TTML локален без TTL. Artist-tags: 30 дней для тегов, 6 часов для пустого результата. Android: ключи lyrics:v2 и :words в SQLite, импортированный текст и разобранные таймкоды в lyrics:local по ID записи. Срок хранения не задан. URI и имя документа не сохраняются | Закрыть Windows-приложение и удалить нужный файл или кэш. Android: импорт нового файла заменяет локальный текст той записи, очистка данных приложения удаляет все тексты. Импорт не обращается к провайдерам. Поля сетевых запросов ниже |
| Экспорт/импорт коллекции для переноса между устройствами | JSON в выбранной пользователем папке или SAF-провайдере. Поля: версия формата, лайки, имена и описания плейлистов, порядок треков, ключи выбранных записей. Метаданные трека: ID, название, артист, длительность, URL обложки, тип версии, просмотры, дата публикации при наличии. Аудио, история и элементы с локальными ID исключаются. Срок не задан | Удалить экспорт там, где он создан. Android вправе записать файл через выбранный файловый провайдер, включая облачный. Прямой сетевой отправки экспорта приложением нет. Импорт дополняет коллекцию и не заменяет имеющиеся данные |
| Резервные копии и миграция | Установщик Windows использует отдельный от приложения профиль. install_kotlin.ps1 сохраняет прежний runtime/EXE в .test-data/before-native-kotlin, он не архивирует SQLite. Локальные ручные копии SQLite могут существовать независимо. У Android allowBackup=false, правила исключают данные из облачного бэкапа и переноса. Срок ручных копий не определён | Управлять и удалять локальные копии вручную. Экспорт коллекции описан отдельно. Внешнего назначения для автоматической резервной копии в проверенном коде нет |
| Диагностика и обработка ошибок | Windows: --diagnose записывает по явно заданному пути или во временную папку. Диагностика создаёт отдельный тестовый профиль. MUSICDESK_UI_REPORT содержит версию, компоненты и факт открытия окна; RIFFUNA_SOURCE_TRACE=1 пишет в source-trace.log отфильтрованные фазы, статусы, типы и транспортные признаки. Срок этих файлов и временного профиля не определён. Android: RiffunaSource/RiffunaAudio в logcat, срок буфера задаёт ОС | Удалить локальный отчёт, трассу и выделенные временные профили вручную или очистить системный буфер. Приложение не отправляет эти отчёты. Живой режим Windows использует фиксированный тестовый запрос и отправляет соответствующий ID видео, а не данные реальной библиотеки |

Удаление всего профиля удаляет коллекцию и предпочтения этого устройства. Windows путь может быть переопределён MUSICDESK_DATA_DIR для изолированных проверок. Приложение не выбирает этот путь само при штатном запуске.

## Поля на внешних границах

- YouTube Music/Innertube: поисковый текст query и фильтр песня/артист/альбом, browse ID/continuation для страниц, video ID для метаданных, воспроизведения и связей артиста, временный контекст сессии клиента, клиента/локаль/регион и параметры воспроизведения библиотеки YouTube.js. Приложение не распаковывает локальную базу в запрос. Проверка вариантов может отправлять запрос, построенный из имени артиста и названия текущего трека.
- YouTube/Google и googlevideo: загрузка версии и JS проигрывателя, публичный идентификатор клиента; в механизме проверки проигрывания отправляются requestKey, ответ скрипта на challenge и одноразовый токен, связанный с ID записи. CDN получает подписанный URL и Range, User-Agent, Accept, Accept-Encoding. Эти временные значения находятся в памяти, аудиокэш хранит сами байты и метаданные проверки. Windows передаёт данные диапазона внутреннему сервису на loopback. Android HTTPS-мост отбрасывает заголовки Cookie и Authorization от WebView. Встроенные публичные клиентские идентификаторы закреплённых библиотек не являются ключом подписи Riffuna.
- LRCLIB: GET /api/get с track_name, artist_name, duration; GET /api/search с track_name, artist_name. В Windows последняя попытка использует только track_name. Duration передаётся в секундах. Android использует Riffuna/Android, Windows — User-Agent приложения и Accept: application/json.
- BetterLyrics: GET /getLyrics и /qq/getLyrics с s (нормализованное название записи), a (исполнитель), d (длительность в секундах); Windows также отправляет пустое al. В запрос не включаются текст песни, история, позиция, ID и путь файла. Оба провайдера получают только метаданные запрашиваемой записи. Пути в полях title/artist подавляются, локальная запись не вызывает ни один из этих запросов. Для запросов текстов автоматические редиректы отключены.
- Статические обложки, storyboard и метаданные: источник получает URL изображения из каталога, возможный параметр размера и обычные заголовки; для проверки видеоряда нужен URL плитки storyboard. Явное «Открыть на YouTube» передаёт браузеру URL с video ID. Системные виджеты Windows/Android получают название, артиста, обложку, состояние и позицию локально.
- Last.fm, Windows: GET /music/<имя артиста>/+tags для отсутствующего локального сопоставления в «Резонансе». Отправляется отдельное имя, а не история, лайки и треки. Происхождение запроса может косвенно показывать интерес к этому артисту.
- GitHub, Windows: проверка имеющейся версии через GET /repos/NikiChaZi/Riffuna/releases/latest, затем запрос контрольных сумм и выбранного установщика. В сеть уходит идентификатор проекта/релиза и имя release asset, библиотека не участвует.

## Проверки

Синтетические JVM-тесты перехватывают Windows HttpURLConnection и Android OkHttp, проверяют точные параметры запросов LRCLIB и BetterLyrics и ответы при искусственной ошибке с данными в сообщении. Отдельно проверяются фильтрация журнала процесса-источника и схема отчёта запуска Windows, а также текст сообщений, передаваемых Riffuna в Android logcat при ошибках. Тесты не отправляют запросы вовне и не используют пользовательский профиль. Проверка APK, Windows runtime, вложенного MSI и экспортируемых CI отчётов ищет базы, приватные профили, файлы ключей, распространённые форматы токенов и подписанные URL. Это проверка известных форматов и мест, а не полная трассировка ОС, сторонних библиотек и удалённых сервисов.

### Проверка GitHub перед предложением настроек

На 16 ноября 2026 публичный REST API вернул protected=false для main, enforcement_level=off и пустой результат rules/branches/main. Обязательного PR и обязательных проверок Windows/Android не обнаружено. Рекомендуемые проверки после успешного PR-запуска — jobs Checks / kotlin и Android APK / apk. Публичный репозиторий подпадает под автоматическое сканирование Secret Scanning по документации GitHub. В ответе security_and_analysis отсутствует, поэтому настройки оповещений и Push Protection отдельно не подтверждены. Публичный .github/dependabot.yml отсутствует. Доступ к GET vulnerability-alerts и к подробностям branch protection требует аутентификации, поэтому флаг Dependabot alerts неизвестен.

Предлагаемые настройки для отдельного согласования: обязательный PR с проверками Windows и Android, Push Protection, Dependabot alerts и security updates, а также конфигурация version updates с пакетами Gradle (обе сборки), npm и GitHub Actions. В этой задаче настройки GitHub не менялись.
