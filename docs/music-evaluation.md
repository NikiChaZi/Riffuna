# Повторная проверка музыкальных рекомендаций — 2026-10-27

Один фиксированный случайный split Music4All-Onion и одна группа из 1000 пользователей, cohort seed 2026. Сиды обучения: 42, 43, 44; модель 42 взята из ранее обученных артефактов, 43 и 44 обучены заново по пять эпох на том же split. ALS обучен отдельно для каждого из трёх сидов.

| Модель | Recall@20, среднее [95% CI] | NDCG@20, среднее [95% CI] |
|---|---:|---:|
| Популярность | 0.01622 [0.01183; 0.02075] | 0.01038 [0.00770; 0.01303] |
| Жанровое сходство | 0.00903 [0.00558; 0.01313] | 0.00506 [0.00304; 0.00742] |
| ALS, 64 фактора | 0.09040 [0.08048; 0.10037] | 0.06361 [0.05571; 0.07152] |
| Two-Tower | 0.03596 [0.02930; 0.04295] | 0.02179 [0.01754; 0.02648] |
| Two-Tower + CatBoost | 0.04542 [0.03933; 0.05187] | 0.03245 [0.02794; 0.03739] |

ALS превосходит текущую двухэтапную модель в этом протоколе. Парная разница Recall@20 (Two-Tower + CatBoost минус ALS): -0.04498, 95% CI [-0.05481; -0.03497].

## Протокол и границы

- ALS: 64 фактора, alpha 20, regularization 0.1, 15 итераций. Используется только train-матрица.
- Контекст и исключение известных треков — tower-train для всех методов. CatBoost получает дополнительные метки из отдельной ranker-части, как в первоначальном протоколе.
- Нейронный retrieval выдаёт реальные top-200 кандидатов. Тестовые цели не добавляются в пул принудительно; проверяется раздельность train/ranker/test.
- 95% интервалы — 2000 иерархических bootstrap-повторов по сидам обучения и одним и тем же пользователям. Для сравнения моделей используется парная разница.
- Результаты относятся к пользователям с историей обучения и одному случайному split. Cold-user, временная и онлайн-оценка не выполнены. Три сида ограничивают выводы о вариативности обучения.
- Измерение выполнено до ограничения числа треков одного артиста и сопоставления с YouTube. Это оценка ранжирования, не вероятность понравиться пользователю.
- Модель в приложении не заменена по результату тестового сравнения. Следующие изменения retrieval/ranker должны проходить отдельный выбор на validation, затем независимую оценку.

## Воспроизведение

```powershell
uv sync --extra dev --extra evaluation --extra recsys
python -m riffuna_recsys.train --seed 43 --output .test-data/music-evaluation/seed-43
python -m riffuna_recsys.train --seed 44 --output .test-data/music-evaluation/seed-44
python -m riffuna_recsys.evaluation --models .test-data/music-training/model .test-data/music-evaluation/seed-43 .test-data/music-evaluation/seed-44 --seeds 42 43 44
```

Опциональный `--library PATH` читает SQLite в режиме read-only и сохраняет только агрегированное покрытие в локальный `library-coverage.json`. Жанровые сервисы при этой проверке не запрашиваются. Личные данные и артефакты обучения не входят в Git.

Числа и SHA256 подготовленных данных: [music-evaluation-results.json](music-evaluation-results.json).
